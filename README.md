# Ревью требований — ИИ-агент проверки спецификаций

Агент проверяет технические задания и спецификации **до начала разработки и тестирования**: выделяет требования с опорой на исходный текст, оценивает каждое по стандартам **ISO/IEC/IEEE 29148:2018** и **IEEE 830-1998**, находит межраздельные противоречия и формирует отчёт на русском языке с оценкой готовности.

Веб-интерфейс и CLI используют один и тот же проверяемый конвейер на TypeScript.

---

## Что умеет агент

- **Точное извлечение требований с проверкой цитат.** Разбирает PDF (с текстовым слоем), Markdown и TXT, сохраняет явные идентификаторы (`FR-1`, `Ф-1` и др.), копирует цитаты напрямую из исходника и отклоняет выдуманные ссылки.
- **Трёхэтапный анализ качества:**
  1. **Инвентаризация требований** — выделение самостоятельных обязательств из текста, списков, таблиц, API-контрактов и критериев приёмки.
  2. **Проверка каждого требования** — оценка однозначности, полноты, атомарности, выполнимости, проверяемости и соответствия формату; для каждого требования определяется выполнимость и готовность к тестированию.
  3. **Проверка набора требований целиком** — поиск конфликтов между бизнес-правилами, REST-контрактами, примерами и приёмкой (до 12 наиболее значимых замечаний, для каждого противоречия требуются две независимые ссылки на исходник).
- **Детерминированная оценка готовности.** Итоговый статус готовности к разработке и тестированию (`Можно начинать` / `После уточнений` / `Заблокировано`) и сводка вычисляются кодом на основе проверенных данных, а не «угадываются» моделью.
- **Режим «FinTech / Банкинг» (feature-flag).** Переключается прямо в веб-интерфейсе, через заголовок `X-Review-Mode: fintech`, переменную `REVIEW_MODE=fintech` или флаг CLI `--fintech`. Дополнительно проверяет банковские и платёжные требования на идемпотентность и дубли событий, точность валют и правила округления, граничные условия (`>` vs `>=`), часовые пояса и периоды расчёта, сторно/возвраты, маскирование PII/PCI и аудит доступа.
- **Предлагаемые формулировки (Before → After) и вкладка «Вопросы команде».** Для дефектов и пробелов агент предлагает готовую улучшенную формулировку на русском языке с кнопкой копирования в один клик. Все уточняющие вопросы автоматически группируются по ролям (**Продукт / БА**, **Разработка**, **Тестирование**, **Безопасность**) и копируются целиком или по отделам для отправки в Slack, Jira или Confluence.
- **Интерактивный split-screen просмотр исходника.** Рядом с отчётом открывается панель исходного документа: клик по замечанию, кнопке **«Показать в тексте»**, цитате или требованию подсвечивает и прокручивает точные исходные блоки (для межраздельных конфликтов подсвечиваются сразу оба фрагмента с быстрыми переходами `[1]`, `[2]`).
- **Устойчивая веб-сессия.** Проверка выполняется в фоне на сервере: при перезагрузке страницы браузер автоматически переподключается к текущей задаче, восстанавливает прогресс или готовый отчёт (хранится в памяти сервера 30 минут). Кнопка **«Отменить»** явно останавливает проверку на сервере.
- **Автообнаружение локальной модели и переключение при лимитах.** Если рядом с сервером запущен локальный LLM-сервер (Ollama / `llama-server`), интерфейс автоматически показывает переключатель провайдера и кнопку быстрого повтора на резервной модели при ошибках квоты (`MODEL_LIMIT`), недоступности (`MODEL_UNAVAILABLE`) или переполнения локального контекста (`MODEL_CONTEXT`). В облаке без локальной модели лишние элементы не отображаются.
- **Экспорт отчётов в PDF, Markdown и TXT.** В PDF встроены шрифты DejaVu Sans (кириллица, спецсимволы), выделяемый текст, кликабельное оглавление и закладки; в Markdown — оглавление с якорями. Все форматы включают режим аудита, предлагаемые формулировки, роли и вопросы автору.

## Архитектура конвейера

```text
PDF / Markdown / TXT (до 10 МиБ, 50 стр., 48 000 символов)
        │
        ▼
[1. Разбор документа]          src/review/document.ts
   Извлечение блоков, разделов, страниц, строк, исходных ID и SHA-256
        │
        ▼
[2. Выделение требований]      src/review/pipeline.ts (extract, ThinkingLevel.LOW)
   Батчи до 50 блоков / 13 000 символов + проверка Zod и верификация всех originalId
        │
        ▼
[3. Проверка поштучно]         src/review/pipeline.ts (individual, ThinkingLevel.LOW)
   Батчи по 12 требований с соседним контекстом + проверка блокирующих дефектов
        │
        ▼
[4. Межраздельный анализ]      src/review/pipeline.ts (set, ThinkingLevel.MEDIUM)
   Сопоставление всего документа + проверка ссылок на существующие блоки
        │
        ▼
[5. Детерминированный отчёт]   src/review/report*.ts
   Дедупликация, приоритизация, вердикт готовности и экспорт в PDF / MD / TXT
```

### Ключевые инженерные решения

- **Защита от галлюцинаций и prompt injection.** Исходный документ передаётся модели как структурированные данные (`JSON`), инструкции из текста спецификации игнорируются, а все ответы модели валидируются через **Zod** и сверяются с реальными блоками документа. При невалидном ответе выполняется автоматический повтор с указанием конкретной ошибки валидации.
- **Адаптивная глубина рассуждений Gemini 4.** Для этапов `extract` и `individual` используется `ThinkingLevel.LOW` (быстрое структурированное извлечение и локальные проверки), а для межраздельного анализа `set` — `ThinkingLevel.MEDIUM`. Встроены автоматические повторы (до 5 попыток) при временных сбоях API и снято ограничение Node `requestTimeout` для длинных потоковых проверок.
- **Безопасность.** Ключ `GEMINI_API_KEY` используется строго на сервере. Опциональный код доступа `REVIEW_ACCESS_CODE` проверяется на сервере через SHA-256 и `timingSafeEqual` на всех маршрутах (запуск, переподключение, отмена) и никогда не сохраняется в хранилище браузера. Локальные запросы и проверка доступности разрешены только на loopback-адреса (`127.0.0.1`, `localhost`, `[::1]`) без редиректов.

## Быстрый старт

Требуется **Node.js 22.13+**.

### 1. Установка зависимостей и настройка ключа Gemini

```bash
npm ci
cp .env.example .env
```

Откройте `.env` и укажите `GEMINI_API_KEY` ([получить ключ в Google AI Studio](https://aistudio.google.com/api-keys)). По умолчанию используется модель `gemini-4-hydrogen`.

### 2. Запуск веб-приложения

```bash
HOST=127.0.0.1 npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000), загрузите файл с требованиями (`.pdf`, `.md`, `.markdown`, `.txt`) и нажмите **«Проверить требования»**.

Для продакшен-сборки:

```bash
npm run build
npm start
```

### 3. Запуск из командной строки (CLI)

```bash
npm run review -- ./requirements.md
```

По умолчанию рядом с исходным файлом создаётся `requirements-report.pdf`. Чтобы выбрать формат, путь или включить расширенный FinTech-аудит, передайте флаг `--fintech` и/или второй аргумент (`.pdf`, `.md`, `.markdown` или `.txt`):

```bash
npm run review -- --fintech ./requirements.md ./reports/review.md
```

## Выбор провайдера моделей

| Провайдер | Как включить | Модель по умолчанию | Лимит входа | Когда использовать |
| --- | --- | --- | --- | --- |
| **Gemini API** | `GEMINI_API_KEY` (по умолчанию) | `gemini-4-hydrogen` | 48 000 символов | Основной режим: высокое качество и скорость |
| **Локальная модель** | `LLM_PROVIDER=local` или запущенный Ollama / `llama-server` | `qwen3.5:9b` | 23 800 байт на запрос | Офлайн-проверка или резерв при лимитах Gemini |
| **Codex CLI** | `LLM_PROVIDER=codex` | `gpt-6.2-sol` | 48 000 символов | Запуск через активную локальную сессию Codex CLI |

### Локальный запуск с Ollama или llama.cpp

Запустите локальный сервер с контекстом не менее `32768` токенов:

```bash
# Ollama
OLLAMA_NO_CLOUD=1 OLLAMA_CONTEXT_LENGTH=32768 ollama serve
ollama pull qwen3.5:9b
LLM_PROVIDER=local npm run review -- ./requirements.pdf ./reports/review.pdf
```

Или через `llama-server`:

```bash
llama-server --model ./qwen3.5-9b.gguf --alias qwen3.5:9b --ctx-size 32768 --parallel 1 \
  --host 127.0.0.1 --port 11439 --reasoning off --no-context-shift
LLM_PROVIDER=local LOCAL_BASE_URL=http://127.0.0.1:11439/v1 \
  npm run review -- ./requirements.pdf ./reports/review.pdf
```

> Если веб-приложение запущено локально одновременно с `GEMINI_API_KEY` и работающим Ollama / `llama-server`, переключение между **Gemini API** и **Локальной моделью** доступно прямо в интерфейсе — без перезапуска сервера.

### Запуск с Codex CLI

```bash
LLM_PROVIDER=codex npm run review -- ./requirements.pdf ./reports/review.pdf
```

На каждом этапе запускается изолированный процесс Codex CLI в режиме только для чтения (без доступа к оболочке, сети и плагинам).

## Переменные окружения

Все поддерживаемые переменные описаны в `.env.example`:

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `GEMINI_API_KEY` | Серверный ключ Gemini API | — |
| `GEMINI_MODEL` | Модель Gemini со структурированным JSON-выводом | `gemini-4-hydrogen` |
| `LLM_PROVIDER` | Провайдер по умолчанию: `gemini`, `local` или `codex` | `gemini` |
| `LOCAL_BASE_URL` | Loopback HTTP-адрес OpenAI-совместимого локального сервера | `http://127.0.0.1:11434/v1` |
| `LOCAL_MODEL` | Имя локальной модели | `qwen3.5:9b` |
| `CODEX_MODEL` | Модель для режима `codex` | `gpt-6.2-sol` |
| `REVIEW_MODE` | Режим проверки по умолчанию: `standard` или `fintech` | `standard` |
| `REVIEW_ACCESS_CODE` | Опциональный код доступа к веб-проверкам | отключён |
| `AGENT_VERSION` | Метка версии агента для паспорта отчёта | git commit или `v1.2.0` |
| `HOST` / `PORT` | Адрес и порт HTTP-сервера | `127.0.0.1` (или `0.0.0.0` в dev) / `3000` |

## HTTP API веб-сервера

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/info` | Статус конфигурации, доступные провайдеры, режим по умолчанию, максимальный размер файла, требование кода доступа |
| `POST /api/review` | Загрузка документа (`application/octet-stream`, заголовок `X-Document-Name`, опционально `X-Review-Mode`, `X-Review-Provider` и `X-Review-Access-Code`); возвращает NDJSON-поток (`started`, `progress`, `heartbeat`, `report` / `cancelled` / `error`) |
| `GET /api/review/:jobId` | Переподключение к выполняющейся или завершённой проверке (восстанавливает прогресс или сразу отдаёт готовый отчёт) |
| `POST /api/review/:jobId/cancel` | Явная отмена выполняющейся проверки на сервере и освобождение слота |

## Публикация в Google AI Studio и Docker

### Google AI Studio Build

1. Импортируйте репозиторий в [Google AI Studio Build](https://aistudio.google.com/apps) (**Add files → Import from GitHub**).
2. Серверный ключ `GEMINI_API_KEY` подключается автоматически через `metadata.json` (`MAJOR_CAPABILITY_SERVER_SIDE_GEMINI_API`); при необходимости его можно сменить в **Settings → Secrets** (например, на ключ с биллингом для повышенных квот).
3. При желании задайте `REVIEW_ACCESS_CODE`, `GEMINI_MODEL` и `AGENT_VERSION` в **Settings → Secrets**.
4. Проверьте работу в **Preview** и нажмите **Publish**.

### Docker / Cloud Run

В корне находится многоэтапный `Dockerfile` (Node 22, запуск от непривилегированного пользователя `node`, порт `8080`). Передайте секреты через переменные окружения контейнера и настройте таймаут запроса под полный цикл проверки.

## Тесты и проверка на примере организаторов

```bash
npm test       # 40 автотестов (разбор PDF/MD/TXT, FinTech-режим, валидация ссылок, провайдеры, отчёты, переподключение и отмена)
npm run check  # проверка типов TypeScript
npm run build  # сборка веб-интерфейса и сервера
```

В тестах используются детерминированные ответы модели, поэтому ключ API для их запуска не требуется.

### Проверка на документе организаторов

```bash
curl -fL 'https://raw.githubusercontent.com/BCC-HUB/ai-requirements-validator-task/928c1aa364265426105b69ba7a3444eac11b22db/docs/requirements.md' \
  -o /tmp/organizer-requirements.md
npm run review -- --fintech /tmp/organizer-requirements.md ./reports/organizer-review.md
```

В отчёте проверьте, что межраздельные конфликты (граница месяца, повторное уведомление при изменении порога, коды ответов REST API) подкреплены ссылками на оба исходных фрагмента.

## Структура проекта

- `src/review/` — парсер PDF/Markdown/TXT, критерии ISO 29148 / IEEE 830, FinTech-аудит, промпты, конвейер валидации, группировка вопросов по ролям, генераторы PDF/Markdown/TXT.
- `src/model/` — клиенты Gemini API, локального OpenAI-совместимого сервера (с loopback-проверкой) и Codex CLI.
- `src/server/` и `src/server.ts` — Express-сервер, фоновые задачи с переподключением и отменой, потоковый NDJSON API.
- `src/cli.ts` — консольный запуск (включая `--fintech`) и атомарное сохранение отчётов.
- `web/` — React-интерфейс (переключатель режима проверки и модели, split-screen подсветка исходника, предлагаемые формулировки, вкладка вопросов по ролям).
- `test/` — модульные и интеграционные тесты (40 тестов).
- `assets/fonts/` — шрифты DejaVu Sans 2.37 и лицензия для кириллицы в PDF.
